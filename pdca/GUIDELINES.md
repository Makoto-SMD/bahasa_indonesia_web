# 組織共通執筆・校正ガイドライン (Editorial Guidelines)

本ガイドラインは、日本人向けインドネシア語学習ナレッジベース（Zensical）を自律的かつ高品質に構築するための品質規約です。
Director、Writer、Reviewer、Engineer、BOSS の全員が本規約を遵守してください。

---

## 1. 記事執筆の基本原則

1. **学習者目線（日本人向け）の解説**:
   - 専門的な言語学用語（文法学術用語）を振り回さず、直感的かつ実用的な解説を心がける。
   - 英語や日本語との対比（例: 「英語の〜に相当」「日本語の助詞とは異なり〜」）を活用して理解を促進する。
2. **例文・用例の充実**:
   - すべての解説には、日常会話やビジネス、旅行でそのまま使える実践的な例文を最低2〜3個付与する。
   - 単語単体ではなく、フレーズや対話（`.dialogue-box`）形式を交える。
3. **視覚的コンポーネントの活用**:
   - インドネシア語例文カード (`.id-example`) を使用する。
   - 接辞の解説では、接頭辞・語根・接尾辞の色分け（`.affix-prefix`, `.affix-root`, `.affix-suffix`）を活用する。

## 2. 表記・マークダウン規約

### 2.1 ルビの廃止方針（カタカナのルビは不要）
- ❌ **インドネシア語の文章・単語にカタカナ等のルビ（`{単語|カタカナ}`）を振ることは不要・禁止**です。
- インドネシア語は英語と同じラテンアルファベットで表記し、ルビを振らずにすっきりと提示します。
- 日本語学習サイト用のルビ拡張機能が残存していた経緯がありますが、インドネシア語学習においては読みにくさや不自然さの原因となるため完全撤廃します。
- 発音の解説が必要な場合は、本文中の発音解説、または独立した発音表記欄で扱います。

### 2.2 日本語括弧・約物と太字（ボールド）記法
- ❌ **`**「強調内容」**` や `**（注記）**` のように、全角約物（鉤括弧や丸括弧）の外側にアスタリスクを配置することは禁止**です。
  - *原因*: Python-Markdown等のパーサーにおいて、半角アスタリスクと全角文字・約物が隣接していると単語境界（word boundary）判定に引っかかり、`<strong>` タグに変換されず `**` がそのままテキストとして露出するため。
- ⭕ **必ず括弧の内側にアスタリスクを配置してください**：
  - 正: `「**年齢の上下を厳格に区別する**」`
  - 正: `『**正式名称**』`
  - 正: `（**注記・補足**）`
  - 複数並ぶ場合: `「**A**」「**B**」`

### 2.3 例文カード記法（ルビなし）
```markdown
<div class="id-example" markdown>

<div class="id-sentence">
Saya mau makan nasi goreng.
</div>
<div class="id-reading">
サヤ マウ マカン ナシ ゴレン
</div>
<div class="id-meaning">
私はナシゴレン（インドネシア風炒飯）が食べたいです。
</div>

</div>
```

### 2.4 対話（会話）ブロック記法（ルビなし）
```markdown
<div class="dialogue-box" markdown>

<div class="dialogue-item">
  <span class="dialogue-speaker">A</span>
  <span>Apa ini?（これは何ですか？）</span>
</div>

<div class="dialogue-item">
  <span class="dialogue-speaker dialogue-speaker--b">B</span>
  <span>Ini kopi.（これはコーヒーです。）</span>
</div>

</div>
```

## 3. コンテンツ形式・学習設計規約

### 3.1 長文読解・ニュース読解のセクション構成順序
読者が長文読解のリズムを崩さず、途中で必要な重要語彙を確認し、最後に日本語訳で答え合わせができるよう、**以下の順序を厳格に統一**します：

1. **インドネシア語長文本文 (`Teks Berita` / `Teks Bacaan`)**:
   - ❌ 段落ごとに日本語訳を交互に挟まない（読解のリズムが崩れるため）。
   - インドネシア語の全文を通しで読めるように `<div class="id-article" markdown>` に格納。
2. **重要語彙とコロケーション (`Kosakata Penting`)**:
   - 本文を読んでいる最中に分からない単語や時事用語をすぐ下で確認できるよう、本文の直後に配置。
3. **日本語訳 (`Terjemahan Berita` / `Terjemahan & Poin Bacaan`)**:
   - 読み終わった後に全体の対訳・意味を確認できるよう、語彙リストの後に配置。
4. **時事構文・文法の解説 (`Poin Tata Bahasa & Struktur Kalimat`)**
5. **背景知識コラム (`Latar Belakang Berita`)**
6. **理解度チェッククイズ (`Uji Pemahaman`)**

### 3.2 語根別派生語マスター図鑑の表現形式
- ❌ **巨大なMermaidダイアグラム（`graph TD`）は使用禁止**。
  - *理由*: ノード数や文字列長が増えるとSVGが自動縮小され、文字が米粒のようになってモバイルやPCで読めなくなるため。
- ⭕ **Markdownテーブル（表形式）を使用する**:
  - `| 派生語 | 品詞・分類 | 主な日本語の意味・ニュアンス |` の見やすい表で整理し、すべてのユーザーがはっきりと読めるようにする。

### 3.3 トップページおよび全体構成の読者本位ポリシー
- ❌ 制作側都合の宣伝や煽り文句（「全500記事の圧倒的網羅性」等）は記載しない。記事数は自然に増加・発展するものであり、読者の学習体験に寄与しない。
- ❌ 開発組織の内情（「自律運用の仕組み」「AI組織」等）はトップページ等の読者向け画面には記載しない。
- ❌ 静的に固定されているにもかかわらず「今日の〜」と謳うようなコンテンツや、読者の学習目的に直結しない装飾コンテンツは配置しない。
- ⭕ 読者が自分のレベルや目的に応じて学習記事を直感的に探せる「体系的ロードマップ」「カテゴリ案内」に徹する。

## 4. ナビゲーションとビルド規約

1. **`zensical.toml` への登録**:
   - 新規記事を作成したら、必ず `zensical.toml` の `nav` の適切なセクションに登録する。
2. **ビルド検証**:
   - 記事作成・修正後は以下のコマンドを実行してエラーがないことを確認する。
   ```powershell
   .\.venv\Scripts\zensical.exe build
   powershell -ExecutionPolicy Bypass -File .\format.ps1
   ```
3. **ポート指定**:
   - ローカルサーバーはポート `8001`（`http://localhost:8001`）を使用する。

---

## 5. バージョン管理・Gitコミット規約

1. **コミット頻度（タイミング）**:
   - **記事が10本程度増えるごと**（セクション完了や一定の節目）。
   - **全体的な修正・リファクタリング・設定変更が行われるたび**。
2. **実行手順**:
   - `zensical.exe build` でノーエラーを確認後、`git add -A` を実行。
   - コミット内容が具体的にわかるメッセージを付与して `git commit` を実行。
   - 例: `feat: add 10 business Indonesian articles (061-070)`
